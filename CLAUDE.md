# Наземное ПО системы «ДРОН-1»

Этот файл Claude читает в начале каждой сессии. Здесь — контекст проекта, роли, правила работы и текущее состояние.
Подробности — в документах (список в п. 9). Главный документ по ядру — «Наземное ПО — ядро (устройство, решения, проверка).docx» в корне.

## 1. Проект

- **Что делаем:** наземное программное обеспечение (НПО) оператора радиационной разведки для работы с дроном «ДРОН-1» через радиолинию.
- **Платформа:** Qt 6 / C++ (Qt 6.7.3, MSVC 2019 64-bit), CMake, Windows, рабочий компьютер оператора.
- **Этап 1 (упрощённый):** до 31.12.2026. **Этап 2 (расширенный):** лето 2027 (идентификация нуклидов, PDF-отчёты, GeoJSON/KML/N42.42, планирование галсов, воспроизведение во времени).
- **Условия:** 1 станция — 1 дрон — 1 оператор; карты офлайн (тайлы MBTiles на диске); хранение — SQLite; интерфейс на украинском и английском; шифрование радиоканала обеспечивает радиомодем (НПО работает с COM-портом).

## 3. Правила работы с Claude

1. Делать только то, о чём просят. Сначала обсуждение, код — по прямой команде («давай код»). Если просят «сразу код» — без описания.
2. Код — целыми файлами (`.h`, `.cpp`) карточками файлов; мелкие правки — пунктами «найди (Ctrl+F) … вставь под / замени на …». `CMakeLists.txt` — целым файлом, сделанным из последнего коммита `dev_A`.
3. Чужой код и комментарии не переписывать и не переформатировать — меняется только необходимое; правки в файлах Никиты (`mainwindow.cpp` и т. п.) — минимальными блоками.
4. Комментарии в коде — по-русски, в стиле Doxygen (`/** @brief … @note … */`, `///<` для полей), подробные.
5. Любая инструкция — пронумерованными шагами, конкретно: какой файл, куда положить, что найти, что вставить, как собрать, как запустить, что должно получиться. Без «имею в виду» — писать точно.
6. Объяснять простыми словами, что и зачем делается. Если спрашивают «о чём ты» / «зачем» — объяснить заново проще.
7. Один шаг за раз: Claude даёт код и проверяет его у себя (сборка, программы проверки) → разработчик вставляет, собирает, запускает проверку → коммит и пуш → Claude проверяет коммит (сверка с выданным) и отвечает таблицей «что проверено — итог».
8. Claude не коммитит и не пушит. Даёт только имя коммита (описания к коммитам не нужны — всё в итоговом документе).
9. Документы — Word-файлом (.docx), по пунктам; таблицы — в Word. Язык общения и документов — русский. Интерфейс — uk/en. Имена файлов — без символов, запрещённых в Windows (`:` и т. п.).
10. Факты о логгере и протоколе — только по коду и документам. Неизвестное — не выдумывать, а записывать в открытые вопросы (п. 8).
11. Ответ — кратко и по делу; если ошибся — признать и исправить без лишних извинений.
12. У каждого класса ядра — своя консольная программа проверки `tests/<имя>_test.cpp` (без окна, без логгера; итог «все проверки пройдены»). Новый класс — сразу в основную программу и в свою программу проверки.

## 5. Архитектура (подробно — итоговый документ, разделы 1–4)

- **DroneCore** (`backend/classes/drone_core.*`) — фасад ядра, единственная точка связи интерфейса с ядром. Живёт в потоке интерфейса, владеет потоком ядра; вызовы — `QMetaObject::invokeMethod`, ответы — сигналы.
- **CoreStub** — заглушка (тестовый полёт), работает при `openPort("STUB")`. **CoreEngine** — настоящее ядро, работает при открытии COM-порта.
- **Классы ядра (в CoreEngine):** DroneLink (Ф1), MessageParser (Ф5), DroneCommands (Ф2), ReconArea (Ф3), LoggerState (Ф4), SessionStore (Ф12, Ф11), SpectrumCollector (Ф10), AlarmManager (Ф8), SdImporter (Ф13), DoseGrid (Ф7, Ф8), DoseCorrection (Ф6, Ф9), CsvExporter (Ф14).
- **Типы** — `backend/classes/core_types.h`. Модули Qt ядра: Core, SerialPort, Sql.
- **Интерфейс** подключён к ядру в `MainWindow::setupCore()` (индикаторы, проверка, карта, тревоги, журнал, спектр).

## 7. Ключевые факты протокола (подробно — «Протокол обмена для наземного ПО»)

- **Порт:** 115200 8N1. **Пакет:** `AA 55 AA 55 | ID | Length (uint16 LE) | Payload | CRC16 (LE) | 0D 0A 0D 0A`, длина 13 + Length. «Без данных»: Length = 1, Payload = 0x01.
- **CRC16:** CCITT-FALSE (0x1021, начало 0xFFFF, без отражения), по ID + Length + Payload; «123456789» → 0x29B1.
- **Приём:** начало по маркеру; длина из Length, конец — на месте; логгер шлёт каждый пакет 2–5 раз, после копии `00 00`; копия = тот же пакет не позже 1 с после предыдущего.
- **Команды:** следующая — только после ответа; повтор без ответа — не раньше 20 с; ответы ID01 (выполнено) / ID02 (ошибка пакета, Payload) / ID03 (запрещено в режиме, условие).
- **Режимы:** проверка → ожидание → разведка → возвращение; авария — выход только выключением питания. Режим определяется по событиям.
- **Данные:** ID19/ID20 (11 байт), ID22 (31), ID23 порция (2055; итог на SD — 2070), ID27 (22), ID25 (1), ID24, ID28. ID10, ID13, ID14, ID17 логгер не передаёт. Отладочные ID70–ID84 — в отладочной сборке (сейчас включена).
- **SD:** `ГГММДД/ЧЧММСС.CSV` (UTC), строка `ID,XX,XX,…`, без Length и CRC; один файл на одну область.
